# AVG / 视觉小说编剧与分镜知识笔记

> 这不是通用写作教程，是**AVG 这一体裁的专门手艺**。
> 核心差异一句话：**小说靠文字讲故事，AVG 靠画面承载信息，文字只补画面给不了的。**
> 掌握了这一条，AVG 的所有规矩就都能推出来了。
>
> 资料来源：GameRes《galgame 分幕/分镜创作和演出制作》、GameRes《实例解说：AVG 演出机制》、
> 286 工作室公开信、Ren'Py/CnGal 编剧手记、以及 Aiming 的场景制作流程。

## 第一层 · 剧本（写什么）

### 1.1 文本框容量 —— 最容易忽略、也最该先定的事

AVG 玩家 90% 的时间在读对话框，所以：

| 指标 | 建议值 | 出处 |
|---|---|---|
| 单行字数 | **8-10 字**，超过就断到下一行 | 《旗帜的传说》对比《火焰之纹章》 |
| 单框行数 | **最多 2 行**（引擎允许可放宽到 3 行） | 多方实践 |
| 单框字数上限 | 商业项目 30-40 字，**超过即不合格** | Aiming《かみながし岛》定 3 行 × 30 字；《星光咖啡馆》定 45 字封顶、55 字是底线 |
| 换行时机 | 不要让句号逗号掉到下一行第一格 | 基础排版常识 |

**为什么要卡这么死？** 因为玩家在推进时，**眼睛移动的成本要算进阅读**。
文字框离角色脸越远，眼睛来回扫的成本越高；行越长，扫视越慢。
这就是为什么「文字盖在说话者身上」的对话框读起来最快。

> 落地上：**写剧本前先去数文本框是几行几列**。
> 这是编译链应该告诉作者的第一个数字（见文末「落到编译链」）。

### 1.2 对白 : 旁白 = 7:3 或 8:2

Galgame 多为第一人称，写第一人的作者容易让内心戏泛滥，
结果就是**女主角傻乎乎看着你思考人生五分钟，笑容僵硬**。

**正确姿势：用角色对话来展现更多信息。**

- 设定与背景 → 靠在角色聊天里透露，不要旁白平铺直叙
- `我说：你为什么打我一巴掌` ✅ 优于 `旁白：她打了我一巴掌`
- 让外界信息**介入或打断**独白，独白成为互动的一部分
- 提问与回答之间**不插思考**（否则读者会问「她在想什么」）

比例不是教条。判断标准是三问：

1. 此刻气氛如何？紧张 → 不该有闲工夫看风景
2. 主角性格如何？谨慎敏感 → 对话推不动时内心戏更多
3. 对白能展现的信息够吗？不够时解说式独白才是必需的

### 1.3 两条铁律

**① 不要为难 CV。**

旁白和独白会原样呈现给玩家，从这个层面看更像小说，**大可以文采飞扬**。
但**对白必须按剧本的样子写**——即使不配音，也要想清楚：

- 说出来够口语化吗？
- 符合这个角色的性格和此刻情绪吗？
- 时长配得上当前气氛吗？
- 方言腔调、口头禅会不会尴尬？

方法：**默念或读出声**。这一条能筛掉大部分 awkward 台词。

**② 信任美术。**

> 「她看起来很生气」——在她已经换了愤怒立绘的当下，这句话是废话。

不要描述立绘和背景已经展示的东西。文字要补的是**立绘画不出的东西**：
内心、回忆、判断、语气里的言外之意。

### 1.4 断句即节奏

这是 AVG 最独特、也最被小说作者忽略的手艺：

- 玩家要点击很多次，所以**每一次点击都是一次「等待下一句」的期待**
- 因此：应该在玩家**最想知道下一句是什么**的地方切，而不是按语法切
- 切得好，玩家会想点；切得平，自动播放就变成合理选择（这是失败信号）

范例（摘自 HuniePop 的文本分析）：

```
我把门打开——★ 在这里切
只是为了确定自己是否该吃掉整块派。
```

切点让读者意识到「Nikki 要进屋了」，下一句的预期被拉起来。
塞进一个框，就浪费了这个钩子。

> **推论：文本框的容量限制，反而是最好的节奏工具。**
> 所以别抱怨「一行放不下」——那是让你学会精简和断句。

### 1.5 其他纪律

- **不用流行语 / 梗。** 生命周期结束后会变成「看不懂的疤痕」。
- **未翻译的外来语、小众捏他** 要谨慎。
- 问句后不插思考，直接进回答。
- 文字格式要能**正则提取**人名/对白/旁白，一键转脚本指令。

## 第二层 · 分镜（怎么拍）

### 2.1 分幕：黑出与红出

幕 = 舞台落下又拉起，代表时间或空间的跨越。

| | 黑出 | 红出 |
|---|---|---|
| 字面 | 撤灯（舞台不落幕） | 落红幕（真正关幕） |
| 用途 | 短暂调度进下一场景；表现同一场景的不同时刻 | 给工作人员调场、演员换装 |
| 时长 | 短 | 长 |
| 频率 | 高 | 一般只在章节末尾 |

**决定分幕的三个条件：时间线索、空间线索、故事发展线索。**

分幕原则：

| 情况 | 处理 |
|---|---|
| 段落已交代清楚，进入下一段 | **分幕** |
| 段落未完，仅因文本量/演出过长 | 分幕（如《魔法使之夜》I/II 段落） |
| 时间大变化，同一情节内（等车、白天转夜） | 黑出，不分幕 |
| 时间变化且已跨情节（激战结束 → 回家疗伤） | **红出，分幕** |
| 空间大变化但渐进（玄关 → 上学路1 → 上学路2 → 校门） | 黑出，不分幕 |
| 空间大变化且突兀 | **分幕** |

### 2.2 分镜的两种流派

| | 导演式 | 舞台式 |
|---|---|---|
| 做法 | 跟着故事脉络分镜 | **先建舞台（世界观），再分镜** |
| 优点 | 情景感/动作感好 | 背景鲜活、**好管理作画** |
| 缺点 | **作画管理耗时最长** | 缺动作连续感 |

导演式的致命问题（《魔法使之夜》数据）：
42 万字文本 → EVENT CG 238 张 + 场景 CG 124 张 + 立绘 20 套 ≈ 400 张，
按市价约 200 万人民币。**做不到就得删减，删减又破坏动作连续感。**

**最佳解：舞台式打底 + 导演式补 CG。**

舞台式说的「世界观」不是空泛设定，而是**可落地的东西**：年代、地理空间、预设的战场。
《FHA》的冬木市就是范例——先定「临海港城 / 以大桥分界的新都与冬木」，
再复用为三咲市，只改地理与年代。地图能反复用、还能在后续作品里继续改。

### 2.3 动势 —— 分镜的呼吸

> **动势** = 画面中核心元素朝某个方向的运动趋势。

- **两个衔接镜头动势同向 → 画面感顺畅**
- **反向 → 画面节奏感更强**

2D AVG 里能表现动势的四种手段：

1. 镜头动势线（特效线）
2. 角色立绘移动
3. 立绘/背景/CG 的单方向振动
4. 角色重影轨迹

> 实战案例：介绍两人时，虚影定格 → 两人立绘**反向移动** + 残影形成轨迹，
> 构成两种动势相反的画面。

### 2.4 立绘的空间逻辑

屏幕上存在一个**不可见的 XYZ 轴**，通常预设几个常用点位（center/left/right 等）。

**关键概念：立绘挂点。**

角色不是「生成在坐标上」，而是**生成在位于角色中心或腰上的挂点**上。
挂点位于三维平面坐标系内。这个设计带来一个重要后果：

> 震动、移动的本质是**移动挂点**。
> 所以震动/移动过程中**可以同时改变立绘表情**，两者不冲突。

挂点分两种视角布局：
- **全身视角** → 五等分点位
- **上半身特写** → 二等分点位

位置只是常用点位，角色可以位于坐标轴任意位置——
**通过调整 XYZ 位置来展现空间关系**（谁在前、谁躲谁身后）。

### 2.5 空镜头的六种时机

不是所有时候都该有立绘。只有背景没有立绘的「空镜头」在这些情况下使用：

1. 角色的动作/立绘**无法用现有机制表现**
2. 需要实现类似**远镜头**的效果（展示环境）
3. 某个角色单独作为主体**心理活动、自言自语**
4. 另一个对话主体**不在一起**（打电话）
5. 需要给某个东西**特写**
6. 希望读者把注意力**放在文字上**（意味深长的桥段）

> 第 1 条有个反直觉的推论（286 工作室）：
> **当人物做出不可表现的动作时，宁愿切掉人物立绘，也不要保留错误的立绘。**
> 例：《秋之回忆 2》里萤打喷嚏时，直接把她的立绘切掉。

### 2.6 景深

| | 适用 | 作用 |
|---|---|---|
| **浅景深** | 人像、某个角色的主视角 | 突出人物，虚化杂乱背景 |
| **深景深** | 风光、建筑、集体合影 | 远近都清晰 |

**景深的突然变化 = 画面重点的突然变化。**
《奥本海默》用浅景深 + 蒙太奇表现精神恍惚，结尾很有冲击力。

### 2.7 2D 里的推拉摇移

2D 也能做出镜头感，靠的是**速度差**：

- 立绘、背景、镜头三者以**不同速度移动** → 平移镜头感
- 让某角色不动、背景动 → 环绕拍摄的效果
- **特写突进/拉远**：在同一张 CG 上来回推，缓慢展示细节

> CG 特写的作用不只是「好看」：
> ① 展示 CG 细节，避免一张 CG 内容过多
> ② **延长一张 CG 的演出时间**（笑）

**决定性画面特写**：选张力最强或最具决定性的瞬间作为一张 CG。

### 2.8 图层优先级（硬规则）

```
文字框 / 头像  >  镜头特效
```

文字框和头像框能做的设计**非常有限**，因为它们承担核心功能：
- 文字框 = 给读者阅读
- 头像框 = 没有立绘时让读者快速分辨说话人

所以这两者**尽量不要整花活**。只有某些特殊题材才值得动。

## 第三层 · 演出（怎么演）

### 3.1 音画错位切（286 工作室）

> 音画是否同时进入，取决于你想多快把情绪推上去或转变掉。

- **情绪骤变** → 音画**同时进入**（场景转场的同时音乐入出）
- **情绪缓变** → 音画**错位进入**（音乐/音效甚至语音先进，然后再转场、再入立绘）

### 3.2 指令组：编排的基本单位

| 类型 | 含义 |
|---|---|
| **指令组** | 多个指令，**互不冲突、可同时执行** |
| **自动指令** | 按流程自动触发直到节点完成（用于多效果前后连续） |
| **延时指令** | 延迟后触发（用于避开同类效果，或让某指令对齐文本） |
| **手动指令** | 需要点击才触发（= 换到下一句对话） |

### 3.3 复合效果要封装

实际配置时不会一一点拼，通常把常用组合封起来命名：

```
fadeout_left（渐变透明离开左）
  = [位置, 速度] + [渐变消失, 完成时间]

shake_up_move（单方向震动移动·上）
  = [震动速度, 幅度, 次数, 方向] + [位置, 速度]
```

**设计时要注意哪些效果组合会程序冲突、哪些会穿帮**，
以及如何用延时和顺序去调节调用。

### 3.4 音的叙事作用

**音效能表达演出机制表达不了的东西**，用来拓展表现维度：

- 踩水声 = 角色走进水坑
- 玻璃破碎 = 有人愤怒地砸了杯子
- 街道白噪音 = 环境很热闹
- 身体碰撞声 = 有人贴上来（能表现立绘做不了的动作）

**BGV 层级**：BGM 音量应低于语音/音效 30-40%。
音效和语音**不要过于频繁**，否则玩家无法集中注意力在文本上——
只在关键处加，用来做**缓急**。而且要保证**关掉声音也能看懂**。

### 3.5 画面元素复用

对资金有限的项目，「恨不得把一个二进制字节掰成两半用」。

- 背景局部、角色肖像（甚至胳膊/腿/上半身）都能单独用
- 立绘：颈部以上的完整头像 → 面部表情，都能穿插进各种演出
- **每增加一张图都要问：还有什么地方能同时用上它？**
- 同一素材做各式特效加工：颜色反转、局部重涂、旧照片效果

## 可量化的节奏指标

| 指标 | 值 |
|---|---|
| 小钩子间隔 | 每 **30-45 秒**一个新信息/物件特写/音乐转场 |
| 台词尾部停顿 | 0.2-0.4s |
| BGM 转场 | 淡入淡出 300-500ms |
| 单框文本 | ≤2 行，8-10 字/行 |
| 立绘同框人数 | 一般**不超过 3 人**（左中右） |
| 说话者突出 | 用**亮暗处理**突出当前说话者 |

## 常见陷阱清单

| 陷阱 | 后果 | 正确做法 |
|---|---|---|
| 路线不平等 | 某条线像事后Thinking | 每条路径都给同等关注 |
| 主角被动 | 玩家只做反应 | 即使玩家驱动，主角也要有实质行动 |
| 说明过载 | 世界观靠讲座灌输 | 让设定自然浮现 |
| 路线重复 | 玩家发现各线雷同 | 有意义地区分 |
| 忽视结局 | 草草收场 | 结局需要有分量 |
| 一段对话不换画面 | **视觉小说读者在等画面** | 一般 1-3 句台词配一张画面；**绝不要 4 句以上不变画面** |
| 文本框塞满 | 读起来是「文字墙」 | 一个框一个想法 |
| 描述画面已有的东西 | 冗余 | 信任美术 |

> 「一个渲染镜头 1-3 行台词」是导演式分镜的经典节奏。
> 4 句以上不变画面，读者就流失了——**视觉小说的读者是在等画面的人。**

## 落到编译链：哪些已经能机械判定

这套知识里能机械判定的部分，已经做成了体检器 ——
`compiler/screenplay.mjs`，**7 类检查 / 70 项测试**：

| 知识点 | 现状 |
|---|---|
| **文本框容量** | ✅ 真机实测的几何真源在 `compiler/textbox.mjs`（内容区 2022×234px、字号 52.48px、行高 2.2em ⇒ 每行 35 全角字 × 2 行） |
| **单框字数 / 行数** | ✅ 体检器检查 1 与 2，超限即报 |
| **标点行首** | ✅ 体检器检查 3：按换行规则预估断点，标出「标点被顶到行首」的病句 |
| **描述了画面已有的东西** | ✅ 体检器检查 4：按「表情指令 × 外观词」的对应关系告警 |
| **对白 / 旁白比例** | ✅ 体检器检查 5 |
| **说话人腔调雷同** | ⚠️ 体检器检查 6，**只做弱信号**——刻意保守，避免体检器自己变成噪音源 |
| **无终局指令** | ✅ 体检器检查 7 |
| **立绘挂点 / 空镜头 / 画中画 / 音量层级 / 音效补位 / 素材复用度** | ❌ 未做。这些属于**演出表达力**，要落在 WebGAL 指令映射的进一步打磨上 |

> **不可机械判定的不进体检**：潜台词、人物一致性、节奏感——
> 宁可少报，也不要让体检器被忽略（**假阳性会训练人忽略输出**）。

### 仍然成立的两条前提

1. **规范必须先变成可执行的检查**，否则它只是美文。体检器就是这个切口：
   写完一拍拍进去，立刻拿到「对白旁白比 / 超长框 / 标点行首 / 表情冗余」的清单。
2. **文本框容量必须持续自描述。** `textbox.mjs` 里的数字是**真机量出来的**，
   不是从 SCSS 推的——换 WebGAL 主题或大版本就得重量一次。
   **没有度量就没有规范。**

## 一页速查

```
【剧本】
  框内 ≤2 行、8-10 字/行；一个框一个想法
  对白:旁白 ≈ 7:3 —— 用对话带信息，别让角色傻站着想
  台词口语化（默念一遍），旁白才可文采
  信任美术：不描述立绘已有的表情
  断句在悬念处，不按语法
  不用流行语；问句后不插思考

【分镜】
  分幕看时间/空间/故事线；渐变黑出，突变红出
  先建舞台再分镜（好管画），导演式补 CG
  动势同向顺、反向强
  震动移动的是挂点 → 可同时换表情
  立绘做不出来的动作，宁可切掉立绘
  空镜头：动作/环境/独白/电话/特写/让读者读文字
  浅景深聚焦，深景深交代
  图层：文字框 > 镜头特效

【演出】
  情绪骤变→音画同入；缓变→错位
  指令组/自动/延时/手动，四种编排单位
  常用复合效果封装成命名块
  BGM 低于语音 30-40%；音效只在关键处
  声音关掉也要能看懂
  一张图问十次：还能用在哪
```
