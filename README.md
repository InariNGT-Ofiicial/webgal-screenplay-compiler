# webgal-screenplay-compiler

> **把一份文字剧本，编译成一部可玩的 WebGAL 视觉小说。**

本项目只做「**剧本 → 游戏**」这一段的自动化：把剧本文本编译成 WebGAL 原生场景文件，
产物丢进**未经一行修改的上游 WebGAL** 就能玩。
渲染、演出、存档格式和 UI 由 WebGAL 提供。Codex 阶段的生产工具已接入 `production/`，用于演出组装、可回退安装、打包验收与可选的章节原生存档适配。

核心 JS 无需 npm 运行依赖；中文词边界增强可选 `segmentit`，不安装时会明确提示。**142 项离线自动化测试**，MIT 许可。

---


## Codex 生产线已接入

`production/` 包含数据化演出、CG 舞台记忆、等比立绘、原生八槽章节存档适配、安装回退、HTTP 试玩与镜像打包。现有编译器通过完整 `game/` 目录接驳，默认逐字节保留正文、分支、配乐、配置和主题。

```sh
npm test
npm run check
npm run demo
```

自己的剧本完成原编译链后运行 `npm run import:compiler`，再用生产安装器部署到一份 WebGAL 发行目录。自动存档通过明确章末锚点启用，要求更换存档标识；详见 [完整接驳步骤](docs/production-integration.md) 和 [集成验证记录](docs/integration-verification.json)。Node.js 22+；零 npm 运行依赖。原作品文本、素材与 WebGAL 引擎均未加入仓库。

## 一、这是什么

一句话：**它不做 VN 引擎，它做 VN 引擎的「上游」。**

两个现成方案之间有一条缝：

| | 它能做什么 | 它给不了什么 |
|---|---|---|
| **WebGAL**（成熟的开源 VN 引擎） | PixiJS 舞台、立绘、Live2D、37 条演出指令、存档、鉴赏、流程图 | ❌ 不含「剧本 → 场景文件」的编译工具链——作者得在官方编辑器里一屏一屏摆 |
| **各种 LLM 小 Demo** | 能让模型吐出剧情 | ❌ 没有引擎抽象层；状态被幻觉污染；离线测不了；也没有能玩的成品 |

本项目的立场：

> **能用别人的，就别自己写。**

渲染层用 WebGAL（成熟、追不上、也不该追）；本项目补的是它缺的那一段——
**把结构化剧本编译成它能吃的场景文件**。

### 为什么不在运行时让模型现写

「每一拍调一次模型，把结果直接推上舞台」是跑得通的——WebGAL 上游就带着一套
编辑器实时预览协议，`preview.command.run-scene-content` 能把**任意脚本文本**
解析成当前场景、还**不要求落盘**。本项目**探索过这条路，最终没有采用**，
因为它要付三个代价：

1. **玩家端零改动。** 编译链的产物是静态文件，WebGAL 一个字节都不用改，
   永远不用跟着上游升级打补丁。
2. **运行时不引入新的失败面。** 编译链的运行时就是 WebGAL 自己；
   运行时注入方案则要依赖**你自己写的那层代码**——它一旦卡住，玩家看到的就是「加载中」。
3. **产物可存档。** 编译链走 WebGAL 原生「开始游戏」入口，
   存档 / 回廊 / 鉴赏 / 流程图**全都在**；注入进去的拍进不了这些系统。

代价是**剧本必须在编译期确定**。这是本项目的适用边界，不是缺陷。

> 那条路线的调研结论没有丢——协议字段、注册方向、以及它的固有代价，
> 都作为 WebGAL 的一手资料记在 [`docs/webgal-redlines.md`](docs/webgal-redlines.md) §3.6。

## 二、编译链长这样

```
┌──────────────────────────────────────────────────────────────┐
│  剧本文本  .docx / .md        ← 你自己的剧本                 │
│  说话人标注 + 场景标题                                       │
└───────────────────────────┬──────────────────────────────────┘
                            │  extract-docx.py  → 结构化 JSON
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  结构化剧本 → 主线指令流（beats.json）                       │
│  docx-to-mainline.mjs                                        │
│  · 断框切分 text-split.mjs · 编辑层表述 editorial.mjs        │
└───────────────────────────┬──────────────────────────────────┘
                            │  build-demo.mjs
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  webgal-tool/dist/game/   ← WebGAL 原生场景文件（落盘）      │
│  章节卡 · 分支跳转 · 背景规则 bg-rules.mjs                   │
│  音效 sfx-rules.mjs · 配乐落点 bgm-cues.mjs · config.txt     │
└───────────────────────────┬──────────────────────────────────┘
                            │  静态文件，一个字都没改
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  WebGAL 4.6.5        上游原样，只读                          │
│  PixiJS 舞台 · 立绘 · 特效 · 转场 · 存档 · 鉴赏 · 流程图     │
└──────────────────────────────────────────────────────────────┘
```

默认编译产物与原生导入模式无需本项目的客户端代码。可选章节存档扩展使用独立运行时操作原生菜单，兼容 WebGAL 4.6.5 中文 UI；启用方式与边界见 [生产线接驳](docs/production-integration.md)。

> ★ 这一行由 `node verify-repo.mjs` 的**探测器 ⑤**对着实测核对（口径 = `compiler/` 下全部 `.mjs` + `.py`）；
> 改过代码就顺手改这里 —— 忘了它会**报红**，不会像以前那样静默漂移。

> 其余脚本只用标准库。**不装也能跑通编译链**，只是没有音效与 docx 抽取。

### 3.2 仓库自检

| 能力 | 实现 | 规模 |
|---|---|---|
| 一键验全仓 | `verify-repo.mjs` —— 依赖解析 / 真实加载 / 资源对齐 / 文档引用 / **文档规模口径**，五个探测器 | 525 行 |
| 探测器自检 | `verify-repo.mjs --selftest` —— 喂**五份故意做坏**的假输入，确认每个探测器都会响（**含一条「散文格必须被跳过」的防误报前置**） | — |
| 语法自检 | `compiler/check-syntax.mjs` —— 全仓脚本一次过（JS + Python 双侧），**带反向自测** | — |

> ★ **分得清「通道坏」和「对象坏」**：两个自检器在探测不到子进程 / python 时，
> 会明确报 **⊘ 未校验**并给出非 0 退出码，**而不是**报「通过」。
> 一个分不清「没查」和「查过了没问题」的校验器没有用。

### 3.3 关键工程结论（踩出来的）

1. **零依赖是可行的，而且很有价值。**
   JS 侧**没有一个 npm 包**——全部只用 `node:` 内置模块。
   收益是 `clone` 下来就能跑，不受依赖漂移影响，也没有许可证传递问题。

2. **文本框上限必须真机量，不能读源码猜。**
   按源码 SCSS 推算出的几何**全错**（产物跑的是另一套主题）。
   实测：每行 35 全角字 × 2 行。而且**超上限不是「难看」，是「整段不渲染」**——
   引擎内部 `textArray.slice(0, lineLimit)` 会静默丢掉超出的文本。

3. **切分器必须单独成模块。**
   埋在转换脚本里时，`import` 就会跑完整转换，根本测不了。
   抽出来后才有 26 项回归测试，包括「**全片每一框都不丢字**」这条不变式。

4. **剧本规范可以变成可执行的检查。**
   「对白旁白比」「单框超长」「标点被顶到行首」「描述了立绘已有的表情」这类问题，
   写手（无论人还是模型）**不会自我察觉**——它没有「文本框装不下」这个感知。
   `screenplay.mjs` 就是给它的那把尺子。

5. **`node --check` 验不了「跑得起来」。**
   它只查语法，**不解析 import**。依赖缺失的文件照样「通过」。
   于是有了 `verify-repo.mjs`：**真起子进程加载**，而不是静态检查。

### 3.4 自动化测试总览

```bash
node verify-repo.mjs                            # 仓库自检（含 --selftest）
cd compiler
node test-screenplay.mjs   #  70 项 · 剧本规范体检器
node test-split.mjs        #  26 项 · 文本断框切分
```

原编译器共 **96 项**；新增生产工具及接驳 **46 项**，合计 **142 项**，全部离线可跑：不需要 API key，不需要任何素材，不需要网络。

> `test-split.mjs` 里有两段「全片回归」断言，验证的是「整部剧的每一框都不丢字」。
> 那两段只有对着真实全片才有意义——本仓库不含剧本文本，
> 所以缺 `mainline/` 时**整段跳过**，而不是降级跑样本（那等于自欺）。

## 四、快速开始

### 4.1 先验环境（零配置）

```bash
node verify-repo.mjs        # 依赖 / 加载 / 资源 / 文档引用 / 规模口径，五个探测器
```

它只需要 Node，不需要任何素材、任何 key。**改了任何脚本之后都该跑一次。**

### 4.2 走完整条链

需要两样东西：① **你自己的剧本文本**（`.docx`，带说话人标注）；② **WebGAL 4.6.5 发行版**。

```bash
python compiler/extract-docx.py 你的剧本.docx    # → 结构化 JSON
node   compiler/docx-to-mainline.mjs             # → 主线指令流
node   compiler/demo-assets.mjs                  # → 占位背景与立绘（纯 Node 手写 PNG）
python compiler/make-sfx.py                      # → 42 条占位音效（纯合成，可跳过）
node   compiler/build-demo.mjs                   # → WebGAL 原生场景文件
node   compiler/verify-sfx.mjs                   # → 音效产物校验（可跳过）
```

> 音效那两步需要 `numpy + scipy`（`pip install numpy scipy`），**不装就跳过**——
> 少了音效不影响场景编译，只是没有环境音与效果音。
> `make-sfx.py` 是**离线合成器**：不联网、不下载、无第三方权利，参数在 `sfx-catalog.json` 里可调。

然后把 WebGAL 发行版解压到 `webgal-tool/dist/`，`build-demo.mjs` 的产物会写进它的 `game/` 目录，
用**任意静态服务器**打开即可。

```bash
python -m http.server 8080 -d webgal-tool/dist     # 然后开 http://127.0.0.1:8080/
```

> ⚠️ **必须走 http，不能双击 `index.html`。** WebGAL 是 `<script type="module">` 且要 `fetch`
> 场景文件，`file://` 下两者都被 CORS 拦掉——页面只剩黑底。这不是 bug，是它的设计。

### 4.3 配乐落点要自己填

`bgm-cues.mjs` 的 `SCENE_CUE` 出厂是**空的**。配乐落点与具体作品绑定，
仓库不含素材，也就无法预设。

不填时 `build-demo.mjs` 会**明确报错并列出「哪些场景没有配乐」**，
而不是默默让全场静音——这是设计：静默降级在 VN 里的表现是**全场静音**或**画面空白**，
比报错难查得多。

## 六、方法纪律（本项目最贵的产出）

以下每一条都是**踩过坑之后**写下来的，不是常识：

1. **同一份规则只能有一处实现。** 切分只有 `text-split.mjs`，文本框容量只有 `textbox.mjs`，
   转义只有 `build-demo.mjs` 里那一个函数。同一逻辑写两遍，早晚会漂移，
   而且**漂移不报错**。
2. **上限必须真机量。** 「源码怎么写」≠「跑起来什么样」。本项目在这上面错过两次。
3. **超上限不是「难看」，是「丢字」。** 引擎会静默丢弃超出实装行数的整段文本。
4. **校验器自身也得被验。** 「永远报绿」和「永远报红」都要防。
   判据：**报错为空 + 全量失败 ≈ 通道坏** ⇒ 先查通道，再信结论。
   （`verify-repo.mjs --selftest` 就是这条纪律的产物。）
5. **验证脚本自己报「空」，先怀疑选择器，别急着怀疑引擎。**
   假阴性会训练人忽略它的输出。
6. **「控制台没报错」≠「画面好」。** 判据只能是像素，且只看**稳态帧**（转场帧不算）。
7. **可回滚的才是可实验的。** 生成物（主题、配置）必须能一键回到上游原样，
   否则一次失败实验就把可交付的东西弄坏了。
8. **别在单引号串里写 `` `${}` ``、别在模板串里写裸反引号。** 不报错，直接进产物。
9. **能静态校验的，不要等到运行时。** 分支跳转的悬空目标、指令的语法体检，
   全部在编译期拦截——因为它们**运行时也不报错，只是不做该做的事**。
10. **`node --check` 通过 ≠ 跑得起来。** 语法检查不解析 import，缺依赖的文件照样「绿灯」。
    验「能不能加载」只有一个办法：**真起进程去加载它**。
11. **移除一块代码前，先算依赖闭包，别按目录归属猜。** 本仓库缩过一次范围，
    原以为「删了 A 会连累 B」，实测依赖图才发现 B 与 A **零交叉引用**——
    按目录名猜会同时犯两种错：删多了，或删不干净。

完整版见 [`docs/pitfalls.md`](docs/pitfalls.md)。

## 七、仓库里有什么、没有什么

### ✅ 有

- **完整编译链**：从 `docx` 到 WebGAL 原生场景文件的全部脚本（JS 侧零依赖）
- ★ **音效的完整配方**：42 条资产的定义 + **离线合成器**（numpy+scipy 按参数合成，
  零下载、零第三方权利），以及可选的 CC0 素材替换通道与出处登记表
- 96 项可离线运行的测试
- 设计文档与方法纪律

### ❌ 没有（**刻意不含**）

| 不含 | 原因 |
|---|---|
| 任何**美术素材**（立绘、背景、CG） | 版权归属各异。仓库改用**纯 Node 手写占位 PNG**，形状可见、零依赖 |
| **BGM 与语音素材** | 同上。★ 音效例外——见上：那些是**合成**的，可以随仓库走（`make-sfx.py` 现场生成） |
| 任何**具体作品的剧本文本** | 作品正文另有归属。示例角色为虚构占位，角色表请替换成你自己的 |
| **主线指令流产物**（`mainline/*.json`） | 由你自己的剧本编译而来。缺产物时脚本会给出**三步提示**，而不是甩 ENOENT 堆栈 |
| **WebGAL 引擎本体** | 上游项目（MPL-2.0），请自行下载（见 §4.2） |

> **音效为什么可以随仓库走**：`make-sfx.py` 是**合成器**，不是素材库 ——
> 42 条资产全部由参数现场生成（枪声、脚步、雨、机房底噪……），
> 想要更真实的声音再走 `fetch-sfx.py` 拉 **CC0**（公有领域，可商用免署名）替换，
> 出处逐条登记在 `sfx-sources.json`。**两条路产出同一批文件名**，可随时互换。

**为什么坚持「零素材」**：一是版权，二是**可验证性**——占位资源是代码生成的，
任何人 clone 下来都能得到一模一样的画面与声音，问题可复现。

## 八、已知边界

- 需要**你自己的剧本**才能跑完整条链。仓库不含剧本文本，也不含编译产物。
- `bgm-cues.mjs` 的 `SCENE_CUE` 出厂为空，**必须先填**（否则编译会明确报错停下）。
- 产物依赖上游 WebGAL 的版本行为；换大版本请重跑 §4.1 的自检。
- 剧情在**编译期**确定。要「运行时由模型现写剧情」，本项目不提供——理由见 §一末。
