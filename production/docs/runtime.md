# 运行时与兼容边界

生产播放使用原生 `start.txt` 和 `changeScene`，因此可以使用 WebGAL 原生存档和回廊。最小本地服务只回复编辑器预览注册并观察舞台快照；不发送 `run-scene-content`，不把原生播放改成逐拍注入。

`release-runtime.js` 必须先于引擎脚本加载。它观察 `stage.snapshot.updated`，读取 `_release_checkpoint` 等变量，通过原生菜单 DOM 写档、读档与确认覆盖，不写 Redux 或私有存档格式。CSS 将原生第一页面展示为四列两行八槽。

## 已验证的配置

- WebGAL 4.6.5 网页发行版；中文原生按钮文案。
- Node.js 24 的本地服务；Node.js 22 为工具最低要求，CI 配置了 22、24，远程尚未运行。
- Chromium 无头模式；运行目录必须走 HTTP。

其他语言、其他主题或引擎版本可能更换按钮文案、DOM 或协议，需重跑浏览器验收。它是一份基于原生 UI 的兼容适配，主题改动会影响它；不承诺跨版本自动兼容。

官方网页版压缩包没有附带两项可选 Live2D SDK。几何 PNG 示例不使用 Live2D，浏览器验收将这两项请求单独记录为 `optionalMissing`；项目场景、美术、音乐的 404 仍导致失败。使用 Live2D 时须自行安装 SDK、处理许可并增加对应验收。

## 保存时序

必须先等原生章节阻塞选择挂载，再打开存档菜单；否则后到的 `choose` 会关闭菜单。覆盖已有档位需等待原生确认框。保存预览出现后等待异步写入，再关闭菜单并选择恢复。

保存失败会保持输入阻断并显示重试按钮，避免玩家点击章节选择而跳过失败的保存；运行时保留错误记录供验收检查。

当前适配器使用原生预览与短暂等待判断写档完成，不能替代浏览器存储实现的事务确认。因此应以真实读档成功作为最终验收；示例 E2E 覆盖了章节档读取、重新保存及覆盖确认。

## 部署

服务默认只监听本机 `127.0.0.1`。它用于本地试玩与封装验收，没有用户认证、多租户或公网管理能力。静态发布时可自行在 HTML 中按顺序引入运行时，但章节自动存档需要与之配套的官方预览快照连接。

`launch.ps1` 使用健康检查校对工程根目录和 PID。`stop.ps1` 校对同一信息后停止对应进程，避免按进程名清理所有 Node 服务。脚本只记录自己的进程，不清理其他工程。
